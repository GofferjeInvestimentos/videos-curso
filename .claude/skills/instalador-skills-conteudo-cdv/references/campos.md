# Campos do config — de onde vem cada um e o que perguntar

O config tem o formato exato de `config-template.md` (o exemplo "Dr. João Silva" é só modelo).
Fontes, nesta ordem de confiança: **PDF de Definição de Audiência e Referências >
site > Instagram > pesquisa na web**.

Legenda: 🟢 sai do material · 🟡 o material sugere, a pessoa confirma · 🔴 só a pessoa sabe

| Campo | Nível | De onde vem | Cuidado |
|---|---|---|---|
| `nome` | 🟢 | PDF de Audiência / Instagram | como ela quer aparecer (com título? "Dra."?) |
| `instagram` | 🟢 | PDF de Audiência | conferir que é o @ certo |
| `bio` | 🟢 | PDF de Audiência / Instagram / site | 1 linha, factual |
| `nicho`, `sub_nicho` | 🟢 | PDF de Audiência | |
| `tese` | 🟡 | PDF de Audiência (o que ela defende) | o que ela FAZ ≠ o que ela QUER dizer — confirmar |
| `inimigos` | 🟢 | PDF de Audiência (dores, crenças erradas, quem atrapalha o cliente) | ideias e práticas, nunca pessoas ou empresas com nome |
| `tom` | 🟡 | PDF de Audiência + Instagram (tom real) | confirmar se o desejado é o atual |
| `palavras_alta_voltagem` | 🟢 | PDF de Audiência (palavras que o cliente usa) | 8–12 termos, na língua do cliente |
| `mitos_do_nicho` | 🟢 | PDF de Audiência (dúvidas e crenças) | 4–6 mitos para desmontar |
| `creators_referencia` | 🟢 | PDF de Audiência ou pesquisa web | 4–6 @ reais; nunca inventar |
| `fontes_nicho`, `podcasts_nicho` | 🟢 | pesquisa web do nicho | |
| `perfis.perfil_dominante` | 🟡 | posicionamento | pessoal / negocio / ambos |
| `produto` | 🔴 | PDF de Audiência / pessoa | o que ela vende |
| `ticket` | 🔴 | PDF de Audiência / pessoa | faixa de preço — NUNCA estimar; fica só no computador dela |
| `conversor` | 🔴 | PDF de Audiência / pessoa | por onde o cliente entra (direct, link, reunião, avaliação) |
| `cta_base`, `cta_lead` | 🔴 | pessoa (pode-se sugerir) | profissão regulada: sem "grátis", desconto ou promessa de resultado; palavra-chave diferente da dos creators de referência |

**Sobre o PDF de Definição de Audiência e Referências:** é dele que saem as dores, os desejos e as dúvidas do
cliente da pessoa — a matéria-prima de `inimigos`, `mitos_do_nicho`,
`palavras_alta_voltagem` e `tese`. Use a direção, com outras palavras; nome de cliente e fala
literal de cliente não entram no config.

## As perguntas (no máximo 5, só as que o material não respondeu)
Faça em linguagem simples, numa mensagem só, numeradas:
1. **O que você vende** e mais ou menos **quanto custa**? (fica só no seu computador; serve
   para as skills saberem para quem você fala)
2. **Como o cliente chega até você** hoje? (manda direct, clica num link, marca uma conversa…)
   E que palavra você gostaria que as pessoas comentassem para receber algo seu?
3. **O que você defende** que a maioria do seu mercado não defende? (confirmo o que entendi:
   "___")
4. **Seu jeito de falar:** mantém o tom que você usa hoje ou quer mudar algo?
5. **Seu conteúdo é mais sobre você** (história, opinião, bastidor), **sobre o negócio**
   (casos, resultados, método) **ou os dois?**

Se a pessoa não souber responder alguma: proponha uma resposta e peça "ok" ou ajuste.

## Antes de instalar, conferir
- [ ] Nenhum campo ainda com o exemplo do "Dr. João Silva"
- [ ] `produto` e `ticket` vieram da pessoa (não estimados)
- [ ] `creators_referencia` com @ reais
- [ ] `perfil_dominante` definido
- [ ] CTA respeita a regra da profissão
- [ ] YAML no formato idêntico ao do modelo
